# STM32F103C8T6 后续接入条件

本文记录 STM32F103C8T6 作为后续接入节点/从设备的前置条件和限制，不纳入当前 ESP32-S3 HTTPS OTA 首期交付。

## 必备接入条件

1. **网络模块驱动**
   - 先明确网络模块型号和接口方式（UART/SPI 等）。
   - 完成模块初始化、联网、断线重连、错误码上报。
   - 驱动层需保留超时和资源释放路径，避免 20KB RAM 环境下长期泄漏。

2. **TCP 服务端**
   - 完成 TCP server 监听、连接接入、收发缓冲、断连清理。
   - 初期建议限制单连接或极少连接数，避免 RAM 被 socket buffer 耗尽。
   - 协议帧需要明确长度、校验、超时和版本字段。

3. **传感器驱动**
   - 完成目标传感器的 I2C/SPI/GPIO 驱动。
   - 记录采样周期、失败重试、异常值过滤和校准参数存储方式。

## 资源约束核对

STM32F103C8T6 典型资源：

- Flash：64KB
- RAM：20KB

接入实现前必须核对：

- 编译后 `.text + .rodata + .data` 是否可放入 64KB Flash。
- `.data + .bss + heap + stack + DMA/socket buffer` 是否可放入 20KB RAM。
- TCP 服务端、网络模块 AT/协议缓冲、传感器采样缓冲必须给出静态预算。
- 初期不建议引入完整 TLS、文件系统、大型日志缓存或动态多连接框架。

## 初期烧录方式

首期固件烧录/调试方式：

- 使用 ST-Link。
- 通过 SWD 接口烧录和调试。
- 保留 SWDIO、SWCLK、NRST、GND、3V3 测试点。

## 后续扩展项

以下能力列为后续扩展，不作为初期接入条件：

- STM32 Bootloader。
- STM32 远程升级/OTA。
- 双镜像或 A/B 分区升级策略。
- 固件签名、加密升级和防回滚。

## 与当前 ESP32-S3 OTA 的关系

当前已实现的是 ESP32-S3 侧 HTTPS OTA、自检和回滚。STM32F103C8T6 后续接入时，应先完成网络模块驱动、TCP 服务端和传感器驱动，并通过 64KB Flash / 20KB RAM 资源核对后，再评估 Bootloader 与远程升级方案。
